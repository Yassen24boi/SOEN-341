# Sprint 1 Work Plan

## Sprint Overview

Sprint 1 focuses on establishing the foundation of CareerConnect. The team will set up the development environment, finalize the initial project requirements, organize the GitHub repository, create the initial user stories, and begin implementing the core functionality of the application.

---

## Sprint Goal

The goal of Sprint 1 is to establish a functional foundation for CareerConnect and deliver the first working features of the platform.

The two primary features targeted for this sprint are:

1. User Registration and Authentication
2. Resume Upload and User Profile Management

---

## Sprint 1 Objectives

During Sprint 1, the team aims to:

- Complete the initial GitHub repository setup.
- Establish the repository structure.
- Configure the GitHub Project Board.
- Define the team's development and Git workflow.
- Complete the project README.
- Create and organize the initial user stories using GitHub Issues.
- Set up the React, Node.js, and MongoDB development environment.
- Implement user registration and login functionality.
- Implement basic user profile management.
- Implement resume upload functionality.
- Perform initial testing of implemented features.
- Document Sprint 1 progress and AI usage.

## Feature 1 — User Registration and Authentication

### Objective

Allow new users to create an account and existing users to securely access CareerConnect.

### Planned Functionality

- User registration
- User login
- Basic input validation
- Password handling
- Authentication error messages
- Logout functionality

### Expected Outcome

A user should be able to create an account, log into CareerConnect using valid credentials, and log out of the platform.

---

## Feature 2 — Resume Upload and User Profile Management

### Objective

Allow users to create and maintain their CareerConnect profile and associate a resume with their account.

### Planned Functionality

- Create a basic user profile
- View profile information
- Edit profile information
- Upload a resume
- View the currently uploaded resume
- Replace/update an uploaded resume

### Expected Outcome

An authenticated user should be able to manage basic profile information and upload a resume associated with their account.

---

## Task Assignment

Tasks will be assigned to team members through GitHub Issues and the GitHub Project Board. Each issue will identify the responsible team member, priority, status, acceptance criteria, and estimated effort.

Team members may collaborate on tasks when frontend, backend, database, or testing work overlaps.

---

## Sprint Workflow

Sprint 1 tasks will progress through the following stages:

**To Do → In Progress → Review → Done**

When a team member begins an assigned task, the corresponding GitHub Issue will be moved to **In Progress**. Once implementation is completed, the work will be submitted for review through a Pull Request.

After the required review and testing have been completed, the work will be merged and the corresponding task will be marked as **Done**.

---

## Definition of Sprint 1 Completion

Sprint 1 will be considered successfully completed when:

- The repository and Project Board are properly organized.
- Initial user stories have been documented as GitHub Issues.
- The development environment is operational.
- User registration and login can be demonstrated.
- Basic profile and resume functionality can be demonstrated.
- Implemented functionality has been reviewed and tested.
- Sprint documentation and AI logs are up to date.
